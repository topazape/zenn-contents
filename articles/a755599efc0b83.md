## はじめに

Python のパッケージ管理は、ここ数年で劇的に改善されました。特に近年は [uv](https://docs.astral.sh/uv/) の登場により、「`pyproject.toml` に依存パッケージを宣言し、`uv sync` で環境を同期する」というシンプルなワークフローがデファクトスタンダードになりつつあります。

一方、[R](https://www.r-project.org/) のパッケージ管理はどうでしょうか。

R で最も広く使われているパッケージ管理ツールは [renv](https://rstudio.github.io/renv/) です。`renv` は `install.packages()` でパッケージをインストールしたあと、`renv::snapshot()`で現在の状態を記録し、`renv::restore()` で復元するという命令的なアプローチを取ります。この「インストールしてからスナップショットを撮る」というワークフローは、`pip freeze > requirements.txt`の時代を思い出させます。

特にデータ分析業務において R と Python を並行して利用する時、R のパッケージ管理にも `uv` 相当のものはないだろうか、と思ったことはありませんか？私はあります。

そんな中、R でも `uv` のようにパッケージが管理できる [rv](https://a2-ai.github.io/rv-docs/) が登場しました。

## rvとは

`rv` は、Rust で書かれた R の宣言的パッケージマネージャです。A2-ai 社が開発し、2025年3月に MIT ライセンスで公開されました。

## renvとの違い

公式のドキュメントでは以下のように違いが説明されています。

> renv は、パッケージを逐次インストールし、事後的にプロジェクトライブラリの現在の状態を「スナップショット」して lock ファイルを生成する、R の従来型パッケージインストールパターンを踏襲しています。これにより、プロジェクトの完全な再現性を妨げる 2 つの問題が生じます。
>
> - 逐次インストールにより、互いに非互換なバージョンのパッケージがインストールされることがある
> - スナップショットが取られる時点では、パッケージがどのようにインストールされたかの情報が失われている
>
> rv はこれらの問題を、依存ツリー全体を事前に解決することで解消します。これにより、非互換なパッケージバージョンが混入するリスクを回避できます。さらに、インストール時点で lock ファイルに記録するため、インストールに関するすべての情報が、事後ではなくその場で捕捉されます。
>
> まとめると、rv の宣言的な設計は、R の初心者にとって十分にとっつきやすく、かつ上級者のニーズにも応えられる形で、動作する完全に再現可能な環境を提供します。

## uv との操作体系の違い

`rv` の操作体系は、`uv` とほぼ同じです。

| `uv` (Python)    | `rv` (R)        | 説明                       |
| ---------------- | --------------- | -------------------------- |
| `pyproject.toml` | `rproject.toml` | プロジェクトの設定ファイル |
| `uv init`        | `rv init`       | プロジェクトの初期化       |
| `uv add <pkg>`   | `rv add <pkg>`  | パッケージの追加           |
| `uv sync`        | `rv sync`       | 環境の同期                 |
| `uv.lock`        | `rv.lock`       | lockファイル（自動生成）   |
| `uv run`         | ─               | Rにはこの概念がない        |

「toml に望ましい状態を書いて、sync で同期する」という概念がそのまま通用します。

## インストール

macOS の場合、Homebrew でインストールできます。

```console
❯ brew install rv-r
```

macOS以外の場合は、公式のインストールスクリプトを使います。

```console
❯ curl -sSL https://raw.githubusercontent.com/A2-ai/rv/refs/heads/main/scripts/install.sh | bash
```

インストールできたか確認します。

```console
❯ rv --version
```

## チュートリアル

### プロジェクトの初期化

適当なディレクトリを作成し、`rv init`でプロジェクトを初期化します。

```console
❯ mkdir my-r-project && cd my-r-project
❯ rv init
```

```console
~/my-r-project
❯ tree
./
├── rproject.toml
└── rv/
    ├── library/
    └── scripts/
        ├── activate.R
        └── rvr.R
```

上記のように `rproject.toml` と `rv/` ディレクトリが生成されます。`rproject.toml` の中身は以下のようになります。

```toml
[project]
name = "tmp"
r_version = "4.5"

# A list of repositories to fetch packages from. Order matters: we will try to get a package from each repository in order.
# The alias is only used in this file if you want to specifically require a dependency to come from a certain repository.
# Example: { alias = "PPM", url = "https://packagemanager.posit.co/cran/latest" },
repositories = [

]

# A list of packages to install and any additional configuration
# Examples:
    # "dplyr",
    # {name = "dplyr", repository = "CRAN"},
    # {name = "dplyr", git = "https://github.com/tidyverse/dplyr.git", tag = "v1.1.4"},
dependencies = [

]
```

私の環境だけかもしれませんが、`rv init` 時に以下の警告が出力され、リポジトリが空の状態で `rproject.toml` が生成されます。

```
WARNING: Could not set default repositories. Set with your company preferred package URL or public url (i.e. `ht
tps://packagemanager.posit.co/cran/latest`)
```

そこで、`rproject.toml` に以下のように CRAN のリポジトリを登録します。

```toml
repositories = [
    { alias = "CRAN", url = "https://cran.r-project.org/" }
]
```

### パッケージの追加

`rv add` でパッケージを追加します。ここでは `--no-sync` オプションをつけて追加だけ行い、インストールは後で実行します。

```console
❯ rv add --no-sync dplyr
```

`rproject.toml` の `dependencies` に `dplyr` が追加されます。

### 何が起きるか確認する

`rv plan` を使うと、`rv sync` を実行した場合に何が起きるかをプレビューできます。

```console
❯ rv plan
```

依存パッケージを含め、インストールされるパッケージの一覧が表示されます。

### 環境の同期

```console
❯ rv sync
```

`rproject.toml` に宣言されたパッケージとその依存が `rv/` ディレクトリ以下にインストールされ、`rv.lock` が生成されます。この lock ファイルには、各パッケージのバージョン、取得元リポジトリ、インストール方法がすべて記録されています。

### 依存ツリーの確認

`rv tree` でインストールされたパッケージの依存関係をツリー表示できます。

```console
❯ rv tree
```

### パッケージの追加と同期を一度に行う

先ほどは `rv add --no-sync` で追加だけ行い、`rv plan` で確認してから `rv sync` で同期しました。`--no-sync` をつけなければ、追加と同期を一度に行えます。

```console
❯ rv add dplyr
```

### R セッションでの利用

`rv init` 時に生成される `rv/scripts/activate.R` により、R セッション起動時に `rv` のプロジェクトライブラリが自動的に読み込まれます。[RStudio](https://posit.co/download/rstudio-desktop/) や [Positron](https://positron.posit.co/) でプロジェクトディレクトリを開き、R セッションを起動すれば、`rv sync` でインストールしたパッケージがそのまま利用可能です。
実際に `my-r-project` ディレクトリを Positron で開くと、以下のようにアクティベートされていることがコンソールの出力から確認できます。

```
rv repositories active!
repositories:
  CRAN: https://cran.r-project.org/

rv libpaths active!
library paths:
  /Users/xxxxxxxx/my-r-project/rv/library/4.5/arm64
  /Library/Frameworks/R.framework/Versions/4.5-arm64/Resources/library
```

## まとめ

R での宣言的なパッケージ管理は今まで存在しませんでしたが、`rv` の登場によりこれが実現できるようになりました。特に Python で `uv` を使用していたユーザーであれば、`rv` をほとんど学習コストなく使い始められます。

日本語の情報がまだほとんどないツールですが、R のパッケージ管理に不満を感じている方は、一度試してみる価値があると思います。
