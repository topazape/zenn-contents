この世に動画サービス A と B が存在するとします。手元には各サービスの利用時間分布があり、A を週 5 時間以上利用する人の割合と、B を週 5 時間以上利用する人の割合はそれぞれ分かっているとします。しかし、両方を週 5 時間以上利用する人がどの程度いるかを把握したくても、これらのデータだけではその割合は分かりません。必要なのは各サービスの利用時間分布だけでなく、同じ人が 2 つのサービスをどう使い分けているかという情報だからです。

なんらかの共通の ID を使って大規模なサービスログ同士を個人単位で結合できれば、この重複は直接集計できます。しかし実務では、ID空間、計測単位、同意、企業間のデータ共有といった制約があり、母集団規模の突合が常に可能とは限りません。一方、各サービス単体の利用時間分布は大規模ログから精度よく分かり、より小規模なシングルソースパネルなら同じ人の両サービス利用を観測できる場合があります。例えば、ユーザーの協力のもと、複数の動画サービスの利用状況を同一人物について収集した調査データなどです。

本記事では、シミュレーションデータを用い、大規模ログと小規模パネルという 2 つのデータをガウシアンコピュラで融合することで、両サービス利用者における利用強度の重複・補完関係を捉えることを目的とします。ただし、分析対象者全員について A と B の両方で正の利用時間が観測されると仮定し、利用有無ではなく利用時間の重複を扱います。

## 周辺分布だけでは決まらないオーディエンス重複

サービス A と B の週次利用時間をそれぞれ $X, Y$ とします。 大規模ログから周辺分布

$$
  F_X(x) = P(X \leq x), \qquad F_Y(y) = P(Y \leq y)
$$

が分かっていても、同時分布 $F_{XY}(x,y)$ は一意に決まりません。たとえば、A と B をそれぞれ週 5 時間以上利用する割合がともに 20% だったとしても、その 20% がほぼ同じ人なのか、ほぼ別の人なのかで、両方のヘビーユーザーの割合は大きく変わります。

最も簡単な仮定は独立です。このとき

$$
  P(X \geq 5, Y \geq 5) = P(X \geq 5)P(Y \geq 5)
$$

と計算できます。しかし、可処分時間、動画への関心、生活習慣などが両サービスの利用に共通して影響するなら、独立仮定は重複を過小評価しやすくなります。

逆に、小規模パネルだけで重複率を直接集計する方法もあります。ただし該当者が少ない組み合わせでは誤差が大きくなります。さらに、パネルの利用時間分布が母集団からずれていれば、その偏りも直接受けます。

## コピュラによる周辺分布と依存構造の分離

コピュラを使うと、同時分布を

$$
  F_{XY}(x,y) = C_\theta\!\left( F_X(x), F_Y(y) \right)
$$

と表せます。$F_X, F_Y$ が各サービス固有の利用時間分布、$C_\theta$ が両者の依存構造です。 この分解により、情報源を次のように分担できます。

| 推定するもの | 使用するデータ          | データから得る情報        |
| ------------ | ----------------------- | ------------------------- |
| $F_X$        | サービス A の大規模ログ | A の利用時間分布          |
| $F_Y$        | サービス B の大規模ログ | B の利用時間分布          |
| $C_\theta$   | 小規模な同一人物パネル  | A と B の順位上の結びつき |

この記事では、依存構造にガウシアンコピュラを使います。実装には [{copula}](https://cran.r-project.org/package=copula) を使用します。

ガウシアンコピュラは、潜在的な標準正規変数 $(Z_X,Z_Y)$ に相関 $\rho$ を置き、

$$
  (Z_X,Z_Y) \sim N\!\left(
    \begin{bmatrix}0 \\ 0\end{bmatrix},
    \begin{bmatrix}1 & \rho \\ \rho & 1\end{bmatrix}
  \right)
$$

とするモデルです。$\rho = 0$ なら独立、$\rho > 0$ なら一方の利用順位が高い人ほどもう一方の利用順位も高い傾向を表します。利用時間そのものに正規分布を仮定するわけではありません。歪んだ分布やサービス間で形の異なる分布は、それぞれ $F_X,F_Y$ が受け持ちます。

## 小規模パネルによる依存構造の推定

パネルサイズを $n$ とします。利用時間をパネル内で順位に変換し $n + 1$ で割ります。これは 0 と 1 が発生するのを防ぐためです。

$$
  U_i = \frac{\operatorname{rank}(X_i)}{n + 1},
  \qquad
  V_i = \frac{\operatorname{rank}(Y_i)}{n + 1}
$$

さらに正規スコアへ変換し、その相関を推定します。

$$
  Z_{Xi} = \Phi^{-1}(U_i), \qquad Z_{Yi} = \Phi^{-1}(V_i),
  \qquad
  \hat\rho = \operatorname{Cor}(Z_X,Z_Y)
$$

重要なのは、依存の推定にはパネル内の順位を使い、利用時間への対応付けには大規模ログの周辺分布を使う点です。偏ったパネルの観測値を母集団の CDF へ直接入れても、一様な擬似観測にはなりません。ただし、パネル内順位を使えば選択バイアスが消えるわけでもありません。この点は後で検証します。

推定した $\hat\rho$ と大規模ログの周辺分布を組み合わせれば、任意の閾値について重複率を計算できます。たとえば

$$
  \begin{aligned}
    P(X \geq 5,Y \geq 5)
    = {} & 1 - F_X(5) - F_Y(5)                         \\
         & +C_{\hat\rho}\!\left( F_X(5),F_Y(5) \right)
  \end{aligned}
$$

です。コピュラによって同時分布を推定できれば、「週3時間以上」「週10時間以上」のように区分を後から変更できるため、よりリッチな情報を使ってさまざまな応用が可能になります。

## シミュレーション設計

### 共通の視聴傾向による利用時間の生成

母集団は50万人とします。各ユーザーの動画視聴傾向を表す共通要因 $H_i$ を置き、週次利用時間を次のように生成します。

$$
  \log X_i = \log 2 + 0.8H_i + \varepsilon_{Ai},
  \qquad
  \varepsilon_{Ai} \sim N(0,0.6^2)
$$

$$
  \log Y_i = \log 1.5 + 0.6H_i + \varepsilon_{Bi},
  \qquad
  \varepsilon_{Bi} \sim N(0,0.8^2)
$$

誤差項は互いに独立で、$H_i$ とも独立とします。$H_i$ は動画への関心、余暇、習慣などをまとめた仮想的な要因とします。$H_i = 0$ のときの条件付き中央値は A が 2 時間、B が 1.5時間になります。

本分析では、視聴傾向がやや高い集団を 20% 含む視聴傾向混合ケースを中心に扱います。

$$
  B \sim \operatorname{Bernoulli}(0.2),
  \qquad
  Z_H \sim N(0,1), \qquad B \perp \!\!\! \perp Z_H
$$

$B$ は混合成分を選ぶスイッチです。$B = 0$ なら通常の視聴傾向を持つ集団、$B = 1$ なら平均が 1.5 だけ高い集団に属します。潜在利用傾向は次のように生成します。

$$
  H_{\mathrm{raw}} = 1.5B + Z_H,
  \qquad
  H = \frac{H_{\mathrm{raw}} - 0.3}{\sqrt{1.36}}
$$

したがって、$H_{\mathrm{raw}}$ の周辺分布は $0.8N(0,1) + 0.2N(1.5,1)$ となります。ここで 1.5 は、2 集団の分離度を定めるシミュレーション上の設定値です。また、$E[H_{\mathrm{raw}}] = 0.3$、$\operatorname{Var}(H_{\mathrm{raw}}) = 1.36$ であるため、$H$ は平均 0、分散 1 に標準化されます。ただし、分布は正規ではありません。したがって、視聴傾向混合ケースではガウシアンコピュラも意図的に近似モデルとなります。

なお、$H \sim N(0,1)$ とすれば $(\log X,\log Y)$ は二変量正規分布となり、真の依存構造はガウシアンコピュラに厳密に対応します。本分析では、より厳しい条件で近似性能を見るため、視聴傾向混合ケースに絞って評価します。

::: details 母集団の生成

```r
set.seed(20260907)

n_population <- 500000
n_panel <- 1000
n_rep <- 100
heavy_thresholds <- c(3, 5, 10)
light_threshold <- 1

population <- tibble(
  b = rbinom(n_population, 1, 0.2),
  z_h = rnorm(n_population, mean = 0, sd = 1),
  eps_x = rnorm(n_population, mean = 0, sd = 0.6),
  eps_y = rnorm(n_population, mean = 0, sd = 0.8)
) |>
  mutate(
    h_raw = 1.5 * b + z_h,
    h = (h_raw - 0.3) / sqrt(1.36),
    x = exp(log(2) + 0.8 * h + eps_x),
    y = exp(log(1.5) + 0.6 * h + eps_y),
    sampling_weight = 0.5 + 0.4 * plogis(1.5 * h)
  )

rho_population <- population |>
  summarise(
    rho = cor(
      qnorm(rank(x) / (n() + 1)),
      qnorm(rank(y) / (n() + 1))
    )
  ) |>
  pull(rho)

population_summary <- population |>
  select(x, y) |>
  cross_join(tibble(heavy = heavy_thresholds)) |>
  mutate(
    a_heavy = x >= heavy,
    b_heavy = y >= heavy,
    a_light = x < light_threshold,
    b_light = y < light_threshold
  ) |>
  summarise(
    fx_h = mean(!a_heavy),
    fy_h = mean(!b_heavy),
    fx_l = mean(a_light),
    fy_l = mean(b_light),
    both_heavy = mean(a_heavy & b_heavy),
    a_heavy_b_light = mean(a_heavy & b_light),
    a_light_b_heavy = mean(a_light & b_heavy),
    .by = heavy
  ) |>
  pivot_longer(
    c(both_heavy, a_heavy_b_light, a_light_b_heavy),
    names_to = "metric",
    values_to = "truth"
  )
```

::: details シミュレーションの実行

```r
panels <- tibble(rep = seq_len(n_rep)) |>
  mutate(
    panel = map(rep, \(.) {
      population |>
        slice_sample(n = n_panel, weight_by = sampling_weight)
    })
  ) |>
  unnest(panel) |>
  mutate(
    u = rank(x) / (n() + 1),
    v = rank(y) / (n() + 1),
    rho_panel = cor(qnorm(u), qnorm(v)),
    panel_h_mean = mean(h),
    .by = rep
  )

panel_summary <- panels |>
  select(rep, x, y, rho_panel, panel_h_mean) |>
  cross_join(tibble(heavy = heavy_thresholds)) |>
  mutate(
    a_heavy = x >= heavy,
    b_heavy = y >= heavy,
    a_light = x < light_threshold,
    b_light = y < light_threshold
  ) |>
  summarise(
    both_heavy = mean(a_heavy & b_heavy),
    a_heavy_b_light = mean(a_heavy & b_light),
    a_light_b_heavy = mean(a_light & b_heavy),
    rho_panel = first(rho_panel),
    panel_h_mean = first(panel_h_mean),
    .by = c(rep, heavy)
  ) |>
  pivot_longer(
    c(both_heavy, a_heavy_b_light, a_light_b_heavy),
    names_to = "metric",
    values_to = "direct"
  )

simulation_raw <- panel_summary |>
  left_join(population_summary, by = c("heavy", "metric")) |>
  mutate(
    copula_u = if_else(metric == "a_light_b_heavy", fx_l, fx_h),
    copula_v = if_else(metric == "a_heavy_b_light", fy_l, fy_h)
  ) |>
  mutate(
    cdf_panel = copula::pCopula(
      cbind(copula_u, copula_v),
      copula::normalCopula(
        param = first(rho_panel),
        dim = 2,
        dispstr = "un"
      )
    ),
    .by = rep
  ) |>
  mutate(
    cdf_population = copula::pCopula(
      cbind(copula_u, copula_v),
      copula::normalCopula(
        param = rho_population,
        dim = 2,
        dispstr = "un"
      )
    ),
    cdf_base = case_when(
      metric == "both_heavy" ~ 1 - fx_h - fy_h,
      metric == "a_heavy_b_light" ~ fy_l,
      metric == "a_light_b_heavy" ~ fx_l
    ),
    cdf_sign = if_else(metric == "both_heavy", 1, -1),
    independence = cdf_base + cdf_sign * copula_u * copula_v,
    fusion = cdf_base + cdf_sign * cdf_panel,
    oracle = cdf_base + cdf_sign * cdf_population
  ) |>
  select(
    rep,
    heavy,
    metric,
    truth,
    independence,
    direct,
    fusion,
    oracle,
    rho_panel,
    panel_h_mean
  )

simulation_long <- simulation_raw |>
  pivot_longer(
    c(independence, direct, fusion, oracle),
    names_to = "method",
    values_to = "estimate"
  )

simulation_summary <- simulation_long |>
  summarise(
    truth = first(truth),
    mean_estimate = mean(estimate),
    bias_pp = 100 * mean(estimate - truth),
    sd_pp = 100 * sd(estimate),
    rmse_pp = 100 * sqrt(mean((estimate - truth)^2)),
    .by = c(heavy, metric, method)
  )
```

### 大規模な周辺データと小規模パネル

各サービスの大規模データには母集団 50 万人の経験分布をそのまま使います。つまり、このシミュレーションでは周辺分布をほぼ既知として扱います。一方、同じ人の $X,Y$ を観測できるパネルは 1,000 人に限ります。

パネルは、共通の視聴傾向 $H$ が高いほど選ばれやすい偏った標本とします。相対抽出重みを

$$
  w(H) = 0.5 + 0.4\operatorname{logit}^{-1}(1.5H)
$$

とします。これは各人の包含確率そのものではなく、非復元抽出で使う相対的な重みです。パネルの周辺分布は母集団からずれますが、今回の設定では依存構造の変化は小さくなっています。

![](/images/audience-modeling-cross-media/fig-joint-usage-1.png)

Figure 1: 非正規の視聴傾向混合ケースから抽出した 5,000 人の週次利用時間. 共通の視聴傾向による両サービス利用時間の正の依存.

### 推定方法の比較

同じパネル抽出を使って、次の5つを比較します。

1.  母集団を直接集計します。シミュレーション上の真値です。
2.  大規模な周辺分布を使い、独立を仮定します。
3.  1,000人のパネルから直接集計します。
4.  大規模な周辺分布とパネル内順位を使い、ガウシアンコピュラで融合します。
5.  母集団全体から $\rho$ を推定したガウシアン近似。モデル誤差を診断するための参考値です。母集団全体の情報を使うため、実務では利用できません。

ヘビーユーザーの閾値は週 3、5、10 時間、ライトユーザーは週1時間未満とします。評価指標は次の3つです。

- 両方ヘビー: $P(X \geq h,Y \geq h)$
- Aヘビー・Bライト: $P(X \geq h,Y < 1)$
- Aライト・Bヘビー: $P(X < 1,Y \geq h)$

母集団を固定したままパネル抽出を 100 回反復し、真値、平均推定値、バイアス、標準偏差、RMSE を求めます。誤差の単位はパーセントポイント (pp) です。

## 精度改善の要因

融合推定の利点は、1,000 人のパネルにすべてを推定させないことにあります。パネル直接集計では、たとえば「A も B も 5 時間以上」というセルに入った人数だけが推定を支えます。対象が希少になるほど有効標本数は減り、推定値は大きく揺れます。

コピュラ融合では、パネルから推定するのは主に 1 つの依存パラメータ $\rho$ です。各サービスで 5 時間以上、1 時間未満となる割合には 50 万人の周辺分布を使います。その結果、パネルが持つ同一人物性は依存の推定へ集中し、周辺分布の標本誤差と偏りを大規模データで置き換えられます。

もちろん、この説明が成立するのは単純な依存モデルが利用構造を十分に近似できる場合に限ります。近似モデルとなる視聴傾向混合ケースでも改善したのは、正規スコア相関で捉えた依存構造が偏ったパネルと母集団の間でほぼ変わらなかったためです。

## 成立に必要な仮定

### パネルから母集団への依存構造の移送可能性

パネル参加を $S = 1$ とすれば、中心となる仮定は

$$
  C_{X,Y \mid S=1} \approx C_{X,Y}
$$

です。パネル参加者における両サービスの利用関係が、母集団でもおおむね同じでなければなりません。

今回の偏りは、動画をよく見る人ほど選ばれやすいというものでした。これによりパネルの利用時間分布はずれますが、両サービスの順位上の結びつきはほぼ変わりませんでした。したがって、今回の結果が示すのは「周辺に偏りがあっても、依存が保たれる条件では融合が機能する」という範囲に限られます。

たとえば、A だけを好む人がパネルへ参加しやすく、B だけを好む人が参加しにくいなら、選択は依存構造そのものを変えます。その場合、大規模ログから正しい周辺分布を入れても、誤ったコピュラは修正されません。属性別の依存推定、較正重み、複数パネル間の比較など、移送可能性を点検する設計が別途必要になります。

### 計測定義の整合性

周辺データとパネルは同じ推定対象を測っている必要があります。

- 観測期間が同じ週次であること
- 利用時間の定義が一致していること
- 人単位と端末単位を混在させないこと
- バックグラウンド再生などの扱いが一致していること

コピュラが扱うのは依存構造であり、計測誤差や推定対象の不一致ではありません。異なるものを測ったデータを結合しても、その不整合は解消されません。

### ガウシアンコピュラによる近似可能性

ガウシアンコピュラは依存を 1 つの相関で表すため、基本モデルとして扱いやすく、多媒体では相関行列へ拡張しやすいモデルです。一方、すべての依存構造を表現できるわけではありません。

たとえば「両方ライト」「両方ヘビー」「A 中心」「B 中心」という異質な集団が混在すると、同じ相関係数でも局所的な重複構造は異なり得ます。また、ガウシアンコピュラには漸近的な裾依存がないため、両媒体の上位 1% が重なる確率のような極端値を重視する場合には、t コピュラなども候補になります。

本記事の週 3、5、10 時間という通常のセグメント閾値ではガウシアンを基準モデルとしました。モデル選択では全体の適合度だけでなく、最終的に使う重複指標をパネル上でどれだけ再現するかを見る必要があります。

## 実データにおける 0 時間の扱い

実際の週次データでは非利用者による 0 時間が多く、同順位が大量に発生するため、連続分布を前提とした順位変換をそのまま適用するのは適切ではありません。この場合は、利用有無と利用者内の正の利用時間を分けて推定します。前者で「両方を利用しない」「Aだけ利用する」といった離散部分を、後者で正の利用時間の依存構造を扱います。

## まとめ

本記事の設定では、大規模なサービスログと小規模なシングルソースパネルの 2 種類のデータをガウシアンコピュラで統合することで、小規模パネルを直接集計するよりも、オーディエンスの重複を安定して推定することができました。

ただし、実データでも同じように機能するとは限りません。パネルで観測されたサービス間の関係が母集団でもおおむね成り立つこと、そして組み合わせるデータ同士で利用時間などの定義がそろっていることが前提です。コピュラ融合はあくまでデータを組み合わせる方法の 1 つであり、パネルの選択バイアスやデータ間の計測定義のずれまで自動的に解消してくれるわけではないことに注意が必要です。
